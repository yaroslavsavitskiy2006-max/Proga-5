## Краткое описание решений

### Задание 1. Пропускная способность записи
Сети хранятся в словаре `{название: tps}`, транзакции за час = `tps × 3600`.
Лидер определяется через `max(d, key=d.get)`.

```
Ethereum: 108,000 транзакций/час
Binance Smart Chain: 576,000 транзакций/час
Solana: 180,000,000 транзакций/час
Лидер: Solana
```

### Задание 2. Операции чтения и записи
При 500 записях/с число чтений: минимум `×100` = 50,000, максимум `×10,000` = 5,000,000.
Оба значения возвращаются кортежем, крупные числа форматируются через `f"{x:,}"`.

### Задание 3. Простейший блокчейн
Класс `Block` с полями `index`, `data`, `prev_hash`; хэш = SHA-256 от строки
`index + data + prev_hash`. Каждый следующий блок хранит хэш предыдущего
(у генезис-блока `prev_hash = "0"`).

```
Блок 0: hash=5408f19d3b30a301... prev=0...
Блок 1: hash=9677ff7745398b4f... prev=5408f19d3b30a301...
Блок 2: hash=978cd3dcd7643f49... prev=9677ff7745398b4f...
```

### Задание 4. Хеширование SHA-256
Функция возвращает `hashlib.sha256(s.encode()).hexdigest()` — 64-символьную
шестнадцатеричную строку.

```
SHA-256('blockchain') =
ef7797e13d3a75526946a3bcf00daec9fc9c9c4d51ddc7cc5df888f74dd434d1
```

### Задание 5. Proof-of-Work
Перебор `nonce = 0, 1, 2, …`, пока хэш `data + nonce` не начнётся с 4 нулей.

```
difficulty=4, nonce=52533
hash=00005d679a4732611132fb28f8cbc90cc513f51a35efca8a6a25bfdab2bf7e69
```

### Задание 6. Корень дерева Меркла
Транзакции хэшируются попарно; при нечётном числе элементов последний
дублируется, пока не останется один корневой хэш.

```
Merkle root: 773bc304a3b0a626a520a8d6eacc36809ac18c0b174f3ff3cdaf0a4e9c64433d
```

### Задание 7. Атака 51%
Угроза есть, если доля мощности `p > 0.5`. Доля выводится как процент
через формат `{p:.0%}`.

```
Доля мощности 30%: безопасно
Доля мощности 51%: УГРОЗА (атака 51%)
Доля мощности 49%: безопасно
Доля мощности 60%: УГРОЗА (атака 51%)
```

### Задание 8. Tangle (DAG)
Первые две транзакции — «вход» в граф. Каждая следующая подтверждает две
случайные предыдущие через `random.sample(range(i), 2)`; `random.seed(42)`
делает результат воспроизводимым.

```
Транзакция 0 подтверждает: — (начальная)
Транзакция 1 подтверждает: — (начальная)
Транзакция 2 подтверждает: [0, 1]
Транзакция 3 подтверждает: [2, 1]
Транзакция 4 подтверждает: [1, 0]
Транзакция 5 подтверждает: [1, 0]
```

### Задание 9. Время подтверждения в IOTA
Формула `t = k / n` при `k = 1000`: чем больше транзакций, тем быстрее подтверждение.

```
n=  10 транзакций -> время подтверждения = 100.00 усл.ед.
n= 100 транзакций -> время подтверждения = 10.00 усл.ед.
n=1000 транзакций -> время подтверждения = 1.00 усл.ед.
```

### Задание 10. Индексатор
Отбор транзакций адреса — через list comprehension по полям from/to.
Баланс = сумма входящих − сумма исходящих.

```
Транзакции Alice (3):
  Alice -> Bob: 50
  Bob -> Alice: 20
  Alice -> Carol: 10
Баланс Alice: -40
```

### Задание 11. Статистика по сабграфам
Запросы суммируются в словарь `d.get(sg, 0) + cnt`; самый нагруженный —
через `max(d, key=d.get)`, общее число — `sum(d.values())`.

```
uniswap: 12,500 запросов
aave: 8,500 запросов
compound: 4,500 запросов
Самый нагруженный: uniswap
Всего запросов: 25,500
```

### Задание 12. Цифровая подпись
Учебная модель: подпись = SHA-256 от `(сообщение + приватный ключ)`,
`verify` пересчитывает подпись и сравнивает. При подмене сообщения
проверка не проходит. Реальный ECDSA использует эллиптические кривые.

```
Подпись: b49fb642b5f7cdcb873df1918 ...
Проверка верной подписи: True
Проверка при подмене сообщения: False
```

### Задание 13. Кубиты
Число квантовых состояний = `2 ** n` (Python поддерживает произвольно большие
целые, 2**127 считается точно).

```
  1 кубит(ов): 2 состояний одновременно | классика: 1 состояний
  2 кубит(ов): 4 состояний одновременно | классика: 2 состояний
  8 кубит(ов): 256 состояний одновременно | классика: 8 состояний
127 кубит(ов): 170,141,183,460,469,231,731,687,303,715,884,105,728 состояний одновременно | классика: 127 состояний
```

### Задание 14. Факторизация
Классическое разложение на простые множители: деление на `d = 2, 3, 4, …`
пока `d·d ≤ n`; остаток `n > 1` — тоже простой множитель.

```
15 = 3 x 5
21 = 3 x 7
91 = 7 x 13
```

### Задание 15. Дорожная карта кубитов
Коэффициенты роста = `next / prev`, средний темп — среднее арифметическое
(считается по неточным значениям, округление только при выводе), прогноз =
последнее значение × средний темп.

```
Поколения кубитов: [127, 433, 1121]
Коэффициенты роста: [3.41, 2.59]
Средний темп роста: x3.00
Прогноз следующего поколения: ~3362 кубитов
```
